# OpenInterview design generation prompt

Copy the complete block; attach the user screenshots when supported. This is a design/prototype request, not an implemented app. See [UI specification](ui-spec.md).

```text
Design the smallest OpenInterview MVP: Vietnamese browser-voice interviews with human-reviewed reports. Generate EXACTLY SEVEN desktop page frames, each 1440 px wide, and a clickable prototype. No mobile/tablet/responsive frames or tasks. No extra auth/callback/error/waiting/profile/history/settings/report/campaign frames, state galleries or modal samples beneath the main UI. Use interaction annotations for overlays, tab content and inline states rather than exploding frames.

All visible copy, accessible labels, policies, errors and generated summaries are simple ENGLISH. Robot/interview speech is VIETNAMESE. Original Vietnamese transcript/evidence remains source data, labelled “Original transcript (Vietnamese)” / “Original evidence (Vietnamese)”, separate from English summaries. No language switch or provider/model changes. Use synthetic data, labelled Example when needed.

EXACT FRAME INVENTORY
1. Home /: compact 56 px OpenInterview / Roles / Sign in navbar with a 30 px logo. One hero: title “Start with a conversation.”, short subtitle “AI leads a short interview. Recruiters review the evidence.” Exactly TWO CTAs: “View roles” and “I have an invitation”, both leading to existing assigned rooms in Roles, via sign-in when needed. No invitation-code management screen. Below hero, ONE large dark-purple preview containing only “Voice interview”, the robot and “Interview language: Vietnamese”. Describe the preview as static in annotations only, not added UI copy; make no live interview claims. No hero badge, Example chip, AI-speaking/waveform or bottom disclaimer. STOP there, matching the screenshot blue box. No workflow/features/bento/FAQ/testimonials/pricing/bottom CTA/marketing footer or links to removed sections.
2. Sign in /login: “Continue with Google”, basic account terms and readable Privacy/Terms text/dialog. No first-profile confirmation/signup wizard. Google callback is a system transition, NOT a frame. Inline pending/cancel/error. No privilege picker or automatic interview start.
3. Roles /roles: one compact profession card list (BA, DevOps, Fullstack, Frontend, Backend, AI Engineer), assigned room rows embedded with schedule/timezone/status and room links. No separate history. “No room assigned” is not a network failure. No self-created practice rooms. One account/logout menu; HR/Admin entries only for permitted users, no profile menu.
4. Join room /rooms/{id}: authorized room details, approved English AI/data/viewers/retention/rights notice and explicit unchecked interview/transcript/report consent BEFORE microphone permission/testing. Policies readable inline/dialog before consent. “Check microphone”, “Test speaker”, “Join interview”; scheduled waiting, denied/expired/revoked, blocked mic and connection errors are inline on THIS page, not extra frames. Contact recruiter inline for CV mismatch before start; candidate has no upload/manage/download CV. No invented policy duration, hidden disclosure or automatic media before consent.
5. Interview /sessions/{id}/interview: ONE large central robot stage and EXACTLY THREE visible controls: “Mute microphone” / “Unmute microphone”, “Mute speaker” / “Unmute speaker”, “End interview”. No navbar/header/sidebar/dashboard shell/timer/volume/device-selector/captions/chat/recording/help/history/profile panels or permanent paragraphs. Short essential status/error text INSIDE stage only, no extra controls including Retry/Leave. End immediately stops safely and returns to Roles with inline “Interview ended”; no confirmation page/dialog or forced spoken wrap, no deletion promise. Backend deadline/delivery/reconnect remain invisible implementation concerns. Platform-owned browser permission dialogs are not app controls.
6. HR /hr: ONE small workspace with Campaigns, Rooms, Reports tabs. Campaigns list + New campaign inline/drawer: bounded JD, role, shared questions/rubric, approved FAQ sources/version lock. Rooms list + Create room inline/drawer: candidate email/name/exact identity, role, locked campaign version, schedule, optional HR-uploaded room-bound CV and Publish invitation. Missing file: “No CV attached”, allowed. File states: Awaiting security check / Available / File rejected / File check failed. Reports list + inline detail/drawer: unverified English summary, original Vietnamese evidence refs, corrections, human approval and controlled retry. No broad directory/calendar/analytics/settings/approval pages or live eavesdropping/mic controls.
7. Admin /admin: minimal users/HR invites and scoped grants plus truthful service/job health metadata, expandable audit metadata. No separate settings/audit/data-request screens, browser secrets/config editor or default content access.

BACKEND ANNOTATIONS, NOT VISIBLE COMPLIANCE CARDS
Every detail/join/token/file request checks identity, scope, assignment, schedule and revocation server-side. Join requires locked approved campaign, valid consent and short-lived room/identity-scoped token. No URL/client-clock bypass. OAuth uses verified identity, state/nonce and safe internal return paths. New users are candidates; HR/Admin grants are controlled.
HR uploads CV only during room creation after verifying authority to disclose and separate lawful basis/notice BEFORE upload; later interview consent is not retroactive. CV optional, HR reference only: no parsing/scoring/AI prompt input and no CV claims as finalized candidate evidence. Draft correction allowed. Publish/invite locks exact room/candidate/campaign plus attachment ID/version/hash or explicit absence. Wrong CV afterward: revoke/cancel old room, create NEW room; never swap ongoing source history. Server validates bounded PDF (5 MB configurable proposal), candidate/room relationship, quarantines and scans before publishing a room containing file. No scan means no publication. Private object store required now, assigned HR/worker-only scoped URLs as needed, not candidate by default; server-only secrets, retention/deletion of copies/backups and tombstones against resurrection.
No candidate profile/CV library/version/share/history/settings portal. No recording/export in active MVP, including disabled controls. No camera/video/chat/coding test, automatic hire/reject, candidate score or invented claims. Internal FAQ answering source remains; not a Home FAQ. Finalized transcript is evidence; planned/partial/unknown output is not. Corrections create new report input/version requiring fresh human review. Durable DB jobs, bounded retries, interruption cancellation and same-session reauthorized reconnect must remain; End works in every state and cannot restart audio on reconnect.

STYLE AND ACCESSIBILITY

Layers/tokens/license have NOT been inspected. Dark/violet screenshots are STYLE ONLY; latest Home blue-box and interview screenshots define SCOPE. Source screenshot dimensions are not requests for extra device frames. Near-black background, restrained violet glow, light readable text, thin borders, simple static/vector robot; minimal workspace chrome. No exact-token extraction or license claim; verify asset rights before reuse.
Keep visible keyboard focus, semantic English labels, readable measured contrast (normal text 4.5:1, large text/essential nontext 3:1), sensible desktop zoom, reduced motion and dialog focus trap/restore. No extra accessibility panel or mobile fallback page. Voice accessibility limitations need review before launch; do not claim compliance from a mockup.
Connect candidate happy path through join consent/device/waiting to interview/end/roles; HR approve/lock → optional attachment/scan → publish → evidence/review. Annotate critical access/consent/mic/reconnect/end/CV-scan/wrong-CV/report-failure edges WITHOUT additional frames. Keep security details in annotations/spec, not visible dashboards. Exactly seven named frames, no extra deliverable pages, no app/test completion claims.
```
